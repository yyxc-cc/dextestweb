# 06 · 流程提示（Runbook）：每一步从哪进、到哪出、什么时候停

> `SKILL.md` 讲"为什么这么做"（原则、坑、证据标准）；
> 这一章讲"现在就做什么"（顺序、输入、产出、完成判据、闸门）。
>
> 新人第一天只读这一篇 + `07-onboarding.md`，就能开工。老手只翻第 9 节（闸门清单）。

---

## 0. 怎么用这一章

- **第一次做**：从阶段 A0 顺序走到 A8，不跳阶段。跳过的阶段，报告里一定缺东西。
- **做过几次**：只翻每个阶段的「闸门」和第 9 节。
- **带新人**：让新人先跑 `07-onboarding.md` 的 30 分钟路径（不碰被测系统），再回来按本章执行。

每个阶段固定五段：**输入 → 动作 → 产出 → 完成判据（DoD）→ 闸门**。
「产出」列出的每一项都必须是**磁盘上真实存在的文件**；只有口头结论 = 这一步没做完。

阶段总览：

| 阶段 | 时间盒 | 主产出 | 一句话目标 |
|---|---|---|---|
| A0 立项 | 30 分钟 | `00-边界.md` | 定范围、定账号、定禁止操作 |
| A1 环境 | 20 分钟 | `config.json`、`.auth/` | 登录跑通一次 |
| A2 摸骨架 | 40~90 分钟 | `census.json` | 拿到"菜单 → URL → 行数 → 分页"表 |
| A3 排优先级 | 20 分钟 | `01-页清单.md` | 决定先测哪 5 页 |
| A4 逐页取证 | 按页 × 15 分钟 | `snap-*.json`、读数记录 | 每页有身份校验 + 三方读数 |
| A5 定级复核 | 30 分钟 | `02-候选缺陷.md` | 每条缺陷两种证据、定级 |
| A6 出图出片 | 按条 × 10 分钟 | `*.png`、`*.mp4`、`*.gif` | 证据可独立看懂 |
| A7 打包 | 30 分钟 | 单文件 HTML + PDF | 双击能看、断网能播 |
| A8 自检交付 | 30 分钟 | 回执 + 未覆盖清单 | 过完 `SKILL.md` 第 7 步清单 |

## 1. 阶段 A0 · 立项与边界（30 分钟）

**输入**：客户/委托人口头需求、被测系统地址、测试账号（或"没有账号"这个事实）。

**动作**（按顺序，不要并行问）：

1. 问清三件事，写下来：**测什么**（哪些模块）、**不测什么**、**什么绝对不能点**。
2. 问清交付形态：报告给谁看（技术 / 老板 / 车间主任）→ 决定详略与用语。
3. 问清测试账号的角色与数据范围（只读账号？只有一个车间？）。
4. 确认是否允许写操作。**默认不允许**；客户口头说"可以随便点"也要追问一句"真的可以建单吗"。
5. 把以上写进 `00-边界.md`（见 `templates/issue.md` 的同款风格，一页纸）。

**产出**：`00-边界.md`，包含：

```
范围：模块 A、B、C（客户提供入口）
不测：模块 D（客户说"不归我管"）→ 报告写"未覆盖 + 原因"
禁止：删除、审核、反审核、批量导入、生产环境写操作
账号：样例账号 readonly-01（占位），角色 = 车间只读
交付：单文件 HTML + PDF，给车间主任看（少术语、多截图）
```

**完成判据**：`00-边界.md` 里"不测"和"禁止"两栏**都不是空的**（空着说明你没问）。

**闸门 · 必须停下来问人**：

- 客户说不出"不能点什么" → 按**全只读**执行，并在报告首段写明这个假设。
- 只有生产环境、没有测试环境 → 停下来，要一句书面确认再动手。
- 客户要求"顺便帮我改一下配置/数据" → 拒绝并记录，这不是测试范围。

**提示词（可直接粘给 Agent）**：

```
你是一名只做只读的外测工程师。现在要测一个我不拥有的 Web 系统（地址占位：http://127.0.0.1:8080/）。
先用 5 个问题帮我把边界钉死：测哪些模块、哪些不测、绝对不能点哪些按钮、账号角色、报告给谁看。
把答案整理成一页《00-边界.md》。在边界没写清之前，不要开始任何页面操作。
```

## 2. 阶段 A1 · 环境与登录（20 分钟）

**输入**：`00-边界.md`、账号、系统地址。

**动作**：

1. `cp templates/config.example.json config.json`。
2. 只改 5 个字段：`baseUrl`、`login` 里三个选择器、`username/password`、`menuContainer`、`readySelector`。
3. 用浏览器开发者工具确认选择器**当前有效**（占位符文案会随版本变）。
4. 跑一次最简登录 + 截图，确认 `config.json` 没有写错。
5. 确认 `.auth/<host>.json` 已生成（下次起免登录）。
6. `ffmpeg -version` 与 `node -v`（≥ 18）各跑一次，记在 `00-边界.md` 末尾。

**产出**：`config.json`、`.auth/<host>.json`、一张登录后的全景截图。

**完成判据**：**第二次**跑同一个脚本时，日志出现"复用登录态"，且截图里能看到菜单——两者都满足才算环境通了。

**闸门**：

- 登录页有验证码 / 短信 / 扫码 → 停下来问人要测试绕行方式；不要尝试破解。
- 登录成功但页面空白 → 先按 `SKILL.md` 第 1 步排查加载时间，不要改选择器硬试。
- 账号是管理员 → 回到 A0 确认"要不要用管理员测权限越界"，否则一律用低权限账号。

**提示词**：

```
读 config.json，逐项核对：登录选择器是否与当前登录页一致、菜单容器与就绪选择器是否能命中。
只读：不要提交任何表单。先跑一次登录并截图，告诉我：登录耗时几秒、菜单项数量、是否生成了 .auth 缓存。
有任何一处对不上，先列出需要我确认的字段，不要自己改。
```

## 3. 阶段 A2 · 摸骨架（40~90 分钟）

**输入**：能登录的 `config.json`。

**动作**：

1. `node scripts/census.js --config config.json`（慢系统加 `--video-dir ./raw` 留全程录像）。
2. 打开 `census.json`，先看三列：`rows`（表格行数）、`pagination`（分页文案里的总数）、`suspectStale`（是否疑似没切页）。
3. 排除 `suspectStale: true` 的页面（读数不可信，等 A4 单独复核）。
4. 找**第一批可疑点**：行数与分页 total 不一致、多个菜单页面指纹相同、接口 4xx/5xx 集中的页面。
5. 把模块清单抄进 `01-页清单.md`（模块 / URL / 行数 / 分页 / 是否可疑）。

**产出**：`census.json`、`01-页清单.md`、可选 `raw/*.mp4`。

**完成判据**：`01-页清单.md` 里每个模块都有 URL 和至少一个数；`census.json` 里被标 `suspectStale` 的页面已单独列出待复核。

**闸门**：

- 遍历过程中弹窗要求"选择期间/组织/仓库" → 停下来问人该选哪个，不要默认第一项（选错会让后面所有读数失真）。
- 某个菜单点了没反应 → 记"疑似点击未生效"，不要立刻写缺陷（可能是加载慢）。
- 数据量巨大的列表（首屏 > 60 秒）→ 停下来对齐：是只抽样，还是换低峰期。

**提示词**：

```
用 census.js 遍历菜单，产出 census.json。然后把结果整理成一张表：模块 / URL / 表格行数 / 分页总数 / suspectStale。
标出三类可疑页面：(1) 行数与分页总数不一致；(2) 连续两个菜单页面指纹相同；(3) 接口 4xx/5xx 最多。
只读，不点任何新增/保存/删除。表格给我之前，先说明你判断"可疑"的依据。
```

## 4. 阶段 A3 · 排优先级（20 分钟）

**输入**：`01-页清单.md`。

**动作**：

1. 按**业务主线**挑页，而不是按菜单顺序：计划 → 下达 → 领料 → 报工 → 检验 → 入库 → 追溯（见 `04-industry.md` 第 2 节）。
2. 每页按风险打分：`数据对不对（高）` > `主流程走不通（中）` > `显示/体验（低）`。
3. 定下前 5 页，写明**为什么是这 5 页**。
4. 剩下的页面写"本轮未覆盖 + 原因"，不要默默省略。

**产出**：`01-页清单.md` 增加"本轮 5 页 + 理由 + 未覆盖清单"。

**完成判据**：5 页里有 ≥ 3 页属于同一条业务链路（能串起来对账）。

**闸门**：

- 客户要求"全部页面都测"但时间只够 5 页 → 停下来谈范围，不要硬扛（最后一定两头不讨好）。
- 主线上的关键页客户说"没做" → 记"未覆盖：功能不存在"，不要去找替代页。

---

## 5. 阶段 A4 · 逐页取证（每页 15 分钟）

**输入**：`01-页清单.md` 里选定的页面。

**动作**（每页固定四步，不许跳）：

1. **身份闸门**：`snap.js --expect-tab "<页签名>"`，对不上就重进，**读数一律作废**。
2. **结构清单**：`snap.js --verbose --json snap-<页>.json`，看页签 / 按钮分级 / 字段 / 列 / 分页 / 弹窗。
3. **三方读数**：页面行数、分页 total、接口 `totalElements` 各记一次（不一致就是候选缺陷）。
4. **筛选扫一遍**：`probe.js --filters "A,B,C"`，逐个筛选看是否都为空（空≠没数据）。
5. 有可疑的，立刻在记录里写下**操作前读数**（后面出片要用）。

**产出**：`snap-<页>.json`、`读数-<页>.md`（每行：项目 / 值 / 来源 / 时间 / activeTab）。

**完成判据**：`读数-<页>.md` 里每条读数都带 `activeTab` 和来源（页面 / 接口 / 导出），没有孤证。

**闸门**：

- 页面读数与接口读数冲突 → **停下来**，先确认"读的是不是同一页 / 同一筛选"，再定性。
- 需要点"保存/提交/审核"才能往下验 → 停下来申请写权限；没批就写"未覆盖"。
- 数值差异涉及业务口径（如 2334 vs 826）→ 停下来问业务，不要判 bug（见 `04-industry.md` 第 8 节三种口径）。

**提示词**：

```
对页面 <URL>（页签：<页签名>）做只读取证，严格按顺序：
1) 先过身份闸门，页签文字对不上就停下并截图，不要继续读数；
2) 输出结构清单：页签 / 工具栏按钮（标注 mutate / reset / read）/ 表单字段 / 表格列 / 分页文案 / 弹窗；
3) 三方读数：页面行数、分页总数、接口 totalElements，三者不一致时列成候选缺陷；
4) 逐个子筛选各跑一次。
不要点任何新增/保存/删除。产出一份《读数-<页>.md》，每条读数标来源和时间。
```

---

## 6. 阶段 A5 · 定级与复核（30 分钟）

**输入**：`读数-*.md`、`snap-*.json`。

**动作**：

1. 每条候选缺陷补齐五要素：前置数据 / 步骤 / 期望 / 实际 / 证据。
2. 按后果定级（P0 数据错丢不可恢复 / P1 主流程断 / P2 显示错 / P3 文案）。
3. **反向复核一次**：换账号、换筛选、换入口，看还能不能复现；不能复现就降为"待确认"。
4. 对照 `04-industry.md` 的 10 条不变量，能挂到具体编号的，写成"违反第 N 条"。
5. 写成 `02-候选缺陷.md`，一条一段。

**产出**：`02-候选缺陷.md`。

**完成判据**：每条都有 ≥ 2 种证据；只有 1 种的，措辞里出现"疑似"。

**闸门**：

- 缺陷依赖客户特例（例如"我们这允许超投"）→ 写"待业务确认"，不要写"确定错误"。
- 同一现象能解释成"上游没传"→ 先查上游，别写给被测系统。
- 想不出"对现场意味着什么"→ 降级为观察项。

**提示词**：

```
把下列候选问题逐条复核，输出《02-候选缺陷.md》。每条必须含：
编号 / 级别 / 页面+URL / 前置数据 / 可重放步骤 / 期望 / 实际 / 证据（截图+视频时间点）/ 影响 / 修复方向（一句话）。
复核规则：能换入口再验一次；只有单一证据的写"疑似"；违反 04-industry.md 不变量的，注明第几条。
不确定业务规则的，标"待业务确认"，并列出要问客户的具体问题。
```

## 7. 阶段 A6 · 出图出片（每条 10 分钟）

**输入**：确认过的缺陷。

**动作**：

1. 干净截图 → `annotate.js` 在四周留白里标注（红缺陷 / 橙待确认 / 绿正常对照）。
2. 数值类缺陷要拍**变化序列**（`1 → 5 → 9 → 13`），每个状态一张。
3. 走查脚本里 `demo.mark()` 打在**动作之前**，收尾 `finishDemo()` 一次切完。
4. 每条缺陷至少一张图；能复现的补 8~15 秒视频片段。
5. 正常模块也拍 1~2 张对照图（证明"这些是有的"）。

**产出**：`01-P0-xxx/`、`02-P1-xxx/` 目录，内含 png / mp4 / gif / 封面。

**完成判据**：把标注全遮掉，原图仍能当证据；把原图遮掉，标注仍能读懂。

**闸门**：

- 截图里没有地址栏/菜单高亮 → 停下来补一次带上下文的截图，别硬发。
- 视频片段过短（< 5 秒）或黑屏 → 重切，不要解释"播放器问题"。
- 涉及客户真实数据（客户名、单价、身份证）→ 停下来问是否脱敏，默认脱敏。

**提示词**：

```
为这条缺陷出证据：先用 annotate.js 做一张带上下文（地址栏、菜单高亮、目标行、分页文案）的标注图，
标注必须落在四周留白里，不遮挡原图任何一个像素；数值类缺陷同时给出变化序列的多张图。
再用 demo.mark() 在动作前打点、finishDemo() 切片，产出 mp4 + 封面 + gif。
文件按 01-P0-<短名>/ 编号命名。产出后自检：图宽 = 原图宽 + 左右留白；mp4 能读出时长。
```

## 8. 阶段 A7 · 打包（30 分钟）

**输入**：`03-报告.md` + 所有证据文件。

**动作**：

1. 报告用固定骨架：范围与边界 → 结论摘要 → 缺陷清单（按级别） → 未覆盖 → 更正表 → 附录（读数原始记录）。
2. `node scripts/md2html.js 03-报告.md` → `node scripts/pack.js --html 03-报告.html --name "客户-模块"`。
3. 生成 PDF 兜底（默认会做；`--no-pdf` 才跳过）。
4. 确认单文件 HTML 断网也能看（视频是 `data:video/mp4`）。

**产出**：`00-问题清单-单文件.html`、`00-问题清单.pdf`、`00-问题清单.md`。

**完成判据**：单文件 HTML 复制到另一台机器、断网，图片和视频都能打开。

**闸门**：

- 报告里出现"应该重新设计"这类越界结论 → 删掉，只留一句修复方向。
- 有测试数据写进系统但现在清不掉 → 停下来先跟客户商量清理方案，再交付。

---

## 9. 阶段 A8 · 自检与交付（30 分钟）

按 `SKILL.md` 第 7 步逐条打勾，再补三条流程性检查：

- [ ] `00-边界.md` 的"不测/禁止"两栏，在报告"未覆盖"一节都出现了
- [ ] 每条缺陷都能指到具体文件 + 时间点，而不是"见附件"
- [ ] 测过的写操作都列成了清单，附清理建议（单号 / id / 原值）

**闸门（交付前最后三问）**：

1. 报告里有没有一句话是"我以为"而没有证据？→ 有就降级或删除。
2. 有没有把"慢"写成"没做"？→ 逐个检查措辞。
3. 客户看完第一页，能不能说出"所以我要先修哪个"？→ 不能就重写结论摘要。

## 10. 一张纸的行动卡（可打印）

```
[A0] 边界写清（测什么/不测什么/禁止什么/给谁看）
[A1] config.json 五处 + 登录跑通 + .auth 生成
[A2] census.json → 三列可疑点 → 01-页清单.md
[A3] 按业务主线选 5 页，写明理由
[A4] 每页：身份闸门 → 结构清单 → 三方读数 → 筛选扫一遍
[A5] 每条缺陷：五要素 + 两种证据 + 定级 + 换入口复核
[A6] 干净截图 + 留白标注 + 动作前打点 + 自动切片
[A7] md → html → 单文件（断网能看）+ PDF
[A8] 自检清单 + 未覆盖 + 写入清单 + 三问
```

> 任何一步"想不起来该干什么"，回到本章对应阶段，看『闸门』那一行——**闸门就是这一步的边界**。
