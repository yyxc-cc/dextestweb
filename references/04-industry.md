# 04 · 工业系统业务课：不懂车间，也能判断对错

> 这一章是给"没下过车间"的人写的。
> 目标不是让你变成工艺工程师，而是让你在看到一页数据时，能问出**内行才会问的那句话**：
> "这 33 件是从哪来的？计划才 4 件。"
>
> 用法：测之前花 20 分钟读第 1~3 节；测的时候把第 4 节的**不变量表**摊在旁边，一条一条对。

---

## 1. 先分清系统版图：谁管什么

工厂里的软件不是"一个系统",是一串。搞不清边界，就会把"上游没传过来"判成"这个模块没做"。

```
        ┌──────────┐   图纸/BOM/工艺     ┌──────────┐
        │   PLM    │ ─────────────────▶ │   ERP    │
        │ 研发/工艺 │                     │ 财务/采购 │
        └──────────┘                     │ 销售/库存 │
                                         └────┬─────┘
                          生产订单/物料需求      │ 发货/收货
                                              ▼
        ┌──────────┐   程序/参数     ┌──────────────────┐
        │  SCADA   │ ◀───────────── │      MOM / MES    │
        │ 设备采集  │ ─────────────▶ │  计划·执行·质量·追溯 │
        └──────────┘   实际产量/状态  └────┬────────┬────┘
                                          │        │
                                    ┌─────▼──┐  ┌──▼─────┐
                                    │  WMS   │  │  QMS   │
                                    │ 仓储/批次│  │ 检验/不合格│
                                    └────────┘  └────────┘
```

| 系统 | 一句话职责 | 它手里的"真相" | 测试时最容易被误判的点 |
|---|---|---|---|
| **ERP** | 管钱、管订单、管总账库存 | 销售订单、采购订单、库存金额 | ERP 的库存是"账面"，不等于车间线边实物 |
| **PLM** | 管图纸、BOM、工艺路线 | 物料定义、版本、替代料 | BOM/工艺改了版本，MOM 没同步 → 不是 MOM 的 bug |
| **MOM/MES** | 管"今天这活怎么干完" | 生产订单、工序、报工、在制、追溯 | 只覆盖执行层，不含财务成本核算 |
| **WMS** | 管库位、批次、出入库 | 批次、库位、效期 | MOM 领料成功 ≠ WMS 实际出库 |
| **QMS** | 管检验、不合格品、放行 | 检验结果、判定、让步接收 | 检验单在 QMS，MOM 只显示结论 |
| **SCADA** | 直连设备，采实时数据 | 设备状态、实际节拍、报警 | 采集断了看起来像"系统卡住" |

**记一句就够**：ERP 管**该不该做**，MOM 管**怎么做完**，WMS 管**料在哪**，QMS 管**能不能放行**，SCADA 管**机器现在什么样**。

> 302MOM 这类国产 MOM，通常把"资源中心（物料/分类/编码）"也放在自己里面，所以你会看到物料主数据既在 ERP 又在 MOM——**两边不一致是常态**，要判"谁是真源"，不能直接判 bug。

### 1.1 行业标准坐标：ISA-95 五层

厂商宣传里的"L3、L4"就是指这个。知道自己在第几层，就不会拿 L4 的规则去要求 L3。

| 层级 | 叫法 | 典型系统 | 管什么 | 测试含义 |
|---|---|---|---|---|
| L4 | 业务计划层 | ERP、SCM | 销售、采购、财务、全局库存 | 交期、成本、账面库存 |
| L3 | 制造运营层 | **MOM / MES** | 排产、执行、质量、追溯、绩效 | 你测的主战场 |
| L2 | 监控层 | SCADA、HMI | 实时监控、报警、配方下发 | 数据从设备来，别当手工录入测 |
| L1 | 控制层 | PLC、DCS | 逻辑控制、联锁 | 一般不经 Web 界面 |
| L0 | 现场层 | 传感器、执行器 | 物理量 | 不在软件测试范围 |

一条实用推论：**L3 的数据要么来自 L4（订单/物料），要么来自 L2（实际产量/设备状态）。** 页面上某个数"不对"，先问它是哪来的——上游没给，不是这一层能修的。

另外两个常被引用的标准：

- **ISO 22400**：给 MOM 的 KPI 定公式。最常用的是 `OEE = 可用率 × 性能 × 合格率`。测"设备效率"页面时，自己按这个乘一遍，对不上就是缺陷。
- **IATF 16949 / GMP**：汽车和医药行业的追溯强制要求（批次正查 + 反查、记录不可篡改）。测追溯页时，"能不能双向查"不是加分项，是硬指标。

## 2. 一张订单在工厂里的旅程（主线）

这是最重要的一张图。**任何页面，你都能在上面找到自己的位置。**

```
销售订单 ──▶ 生产计划(MRP) ──▶ 生产订单 ──▶ 派工/下达 ──▶ 领料
   │             │                │            │           │
   ▼             ▼                ▼            ▼           ▼
 交期         物料需求          工单号        工序任务     批次/库位
                                              │
                          ┌───────────────────┘
                          ▼
                    开工(首件) ──▶ 过程检验 ──▶ 报工(数量/工时) ──▶ 完工入库
                          │            │              │              │
                          ▼            ▼              ▼              ▼
                      设备/工装     合格/不合格      产出+报废+在制    批次追溯
                          │            │
                          └──▶ 异常(停线/返修/让步) ──▶ 闭环
```

每一步在系统里对应什么、测什么：

| 环节 | 系统里叫什么 | 关键字段 | 该问的问题 |
|---|---|---|---|
| 计划 | 生产订单 / 工单 | 订单号、物料、计划数量、计划开工/完工 | 计划数量能不能小于已投数量？ |
| 下达 | 工单下达 / 派工 | 状态、工序号、工作中心 | 未下达能不能报工？ |
| 领料 | 领料单 / 发料 | 批次、数量、库位 | 领料数 > BOM 用量时会不会拦？ |
| 开工 | 开工 / 首件 | 实际开始时间、设备、班次 | 开始时间能早于计划日期吗？ |
| 检验 | 首检 / 巡检 / 完工检 | 检验项、判定、抽样数 | 不合格能不能继续报工？ |
| 报工 | 报工 / 产出申报 | 合格数、不合格数、工时、报废 | 合格+不合格+报废 = 投入吗？ |
| 入库 | 完工入库 | 批次、数量、库位 | 入库数能大于报工合格数吗？ |
| 追溯 | 批次追溯 / 谱系 | 上料批次、产出批次 | 断链了能不能查到？ |

**主线测试法**：不要一页一页孤立地测。挑一条真实工单，从"计划"走到"入库"，每一步记下数量。走完对一次总账——**对不上，就是缺陷；对得上，你就有了整条链的证据。**

## 3. MOM 的 12 个核心对象

看到不认识的页面，先判断它属于哪个对象。

| # | 对象 | 现场叫法 | 是什么 | 关键字段 | 常见错法 |
|---|---|---|---|---|---|
| 1 | 物料主数据 | 料号、物料卡 | 一个东西的"身份证" | 编码、名称、规格、单位、物料性质 | 编码重复；单位为空；一物多码 |
| 2 | 物料分类 | 大类/中类/小类 | 物料的树形归类 | 分类编码、层级、父节点 | 循环父子；同一物料挂两个末级 |
| 3 | BOM | 配方、用料表 | 做一个成品要哪些料、各多少 | 父件、子件、用量、损耗率、版本 | 循环引用；用量为 0；版本不生效 |
| 4 | 工艺路线 | 路线、工序表 | 按什么顺序、在哪个工位做 | 工序号、工序名、工作中心、工时 | 工序号重复；跳序；路线与工单不符 |
| 5 | 工作中心 | 产线、机台、工段 | 干活的地方/设备组 | 编码、产能、所属车间 | 产能为 0；重复归属 |
| 6 | 生产订单 | 工单、制令 | 一次生产任务 | 单号、物料、计划数、状态、交期 | 状态倒退；计划数被改小 |
| 7 | 工单工序 | 工序任务 | 工单拆到每道工序 | 工序号、计划/完成数、状态 | 完成数 > 计划数无提示 |
| 8 | 派工 | 排班、任务分派 | 把工序派给人/班组/设备 | 人员、班次、开始结束 | 同一人同一时段两单 |
| 9 | 报工 | 产出申报、扫码报工 | 干了多少、多久、废了多少 | 合格数、不合格数、工时、时间 | 重复报工；时间倒挂；超报 |
| 10 | 领料/退料 | 发料、退库 | 从仓库拿料/退回去 | 物料、批次、数量、库位 | 超领不拦；退料不回冲 |
| 11 | 在制品(WIP) | 在制、线上料 | 已经投进去还没产出的部分 | 工单、工序、数量 | 投入≠产出+废+在制 |
| 12 | 质检/追溯 | 检验单、谱系 | 合不合格、这批料去了哪 | 检验项、判定、批次链 | 不合格品流入下道；追溯断链 |

> **物料 vs 资源**：很多 MOM 把"人、机、料、法、环"统称资源。看到"资源管理"别以为是文件资源——在制造业语境里，它八成是**物料主数据**。判断方法：看字段里有没有"物料编号/规格型号/计量单位"。

### 3.1 拿 MESA 的 11 个功能块当"测试范围清单"

国际上描述 MES/MOM 功能，最常引用的是 MESA-11 模型。**客户没给测试范围时，就拿这 11 条去对系统菜单**，缺哪块就写"未覆盖 + 客户未提供入口"，而不是漏掉不提。

| # | 功能块 | 系统里大概叫什么 | 关键测试点 |
|---|---|---|---|
| 1 | 资源分配与状态 | 资源管理、设备台账 | 资源唯一、状态与实际一致 |
| 2 | 工序详细排产 | 排产、计划编排 | 同一设备时段不重叠 |
| 3 | 生产单元派工 | 派工、任务分派 | 派给不存在的人/停机设备应拦 |
| 4 | 文档管理 | 图纸、作业指导书 | 版本与工单匹配、旧版不生效 |
| 5 | 数据采集 | 报工、扫码、设备采集 | 重复上报、时间戳、单位 |
| 6 | 劳动管理 | 工时、考勤、班组 | 工时合计 ≤ 班次时长 |
| 7 | 质量管理 | 检验、不合格品 | 不合格不能流入下道 |
| 8 | 过程管理 | 工艺参数、报警 | 参数超限有记录、可追溯 |
| 9 | 维护管理 | 设备保养、点检 | 保养到期提醒、记录不可改 |
| 10 | 产品跟踪与谱系 | 批次追溯 | **正查 + 反查都要通** |
| 11 | 绩效分析 | OEE、产量看板 | KPI 公式自己算一遍 |

> 用法：一行一行问"这个系统有没有"。有 → 进去按关键测试点验；没有 → 问客户"是没做，还是不用测"。**这两种情况在报告里写法完全不同。**

### 3.2 KPI 页面怎么验：OEE 是最常见的坑

`OEE = 可用率 × 性能 × 合格率`

| 指标 | 公式 | 常见错法 |
|---|---|---|
| 可用率 Availability | 实际运行时间 ÷ 计划生产时间 | 把停机算成运行；计划时间取错班次 |
| 性能 Performance | （理想节拍 × 产量）÷ 实际运行时间 | 理想节拍拍脑袋；产量含报废 |
| 合格率 Quality | 合格数 ÷ 总产出 | 分母漏了返修 |

验法：**把三个分项和总数一起抄下来，自己乘一遍。** 乘积对不上 OEE，就是缺陷（或口径没写清，写"待确认"）。这比"感觉这个数偏低"有力得多。

## 4. 十条硬不变量（背下来就能判对错）

这十条是**跨行业、跨厂商都成立**的。页面违反了其中任何一条，基本可以直接写缺陷，不需要问业务。

| # | 不变量 | 大白话 | 页面怎么验 |
|---|---|---|---|
| 1 | **数量守恒** | 投进去的 = 好的 + 坏的 + 还在做的 | 投入 100，合格 80，报废 5 → 在制必须是 15 |
| 2 | **不能超计划**（除非明确允许） | 计划 4 件，不能报工 33 件还一声不吭 | 报工数 > 计划数 − 已完成数 时，应有提示或拦截 |
| 3 | **时间不倒流** | 完工不能早于开工，报工不能早于派工 | 比较同一单据内的几个时间字段 |
| 4 | **状态单向** | 已审核→已下达→生产中→已完工，不能往回跳 | 反复点按钮，看状态是否回退 |
| 5 | **已审核不可改** | 审核过的单据改数量，等于账做了两遍 | 找已审核单据，看编辑按钮是否还在/能否保存 |
| 6 | **唯一性** | 物料编码、工单号、工序号在同一范围内唯一 | 用同一编码再建一次，看是否拦 |
| 7 | **引用完整性** | 被工单引用的物料不能直接删 | 找有引用的对象点删除，看是拦截还是报 500 |
| 8 | **明细合计 = 表头** | 明细行加起来必须等于表头总数 | 有主子表的页面，自己加一遍 |
| 9 | **单位/精度一致** | 1 吨 = 1000 千克，不能 1 吨 = 100 千克 | 换单位后看数量是否按换算率变 |
| 10 | **口径一致** | 同一个"总数"，列表、分页、导出、看板必须一样 | 列表 total vs 导出条数 vs 首页卡片 |

### 怎么用这张表（三步）

1. **先找数字**：页面上所有能加、能比的数（数量、条数、金额、工时）。
2. **再找关系**：它们之间应该满足哪条不变量？
3. **最后验**：自己算一遍，或者换个入口看同一个数。

> 302MOM 资源中心的"综合查询 2334 条 vs 分类查询 826 条"，就是第 10 条（口径一致）的典型。**先别判 bug**——两个入口的过滤范围可能本来就不同。正确做法是证明"一个是另一个的子集"，再问"差的 1508 条为什么不在分类树里"。

### 4.1 状态机：拿按钮灰不灰来验

工业单据几乎都有状态，且**只能单向走**。典型值：

```
草稿/新增 ──下达──▶ 已下达 ──开工──▶ 生产中 ──完工──▶ 已完工 ──关闭──▶ 已关闭
   │                    │                  │
   └──取消──▶ 已取消     └──撤销──▶ 草稿?   └──返工──▶ 返修中 ──▶ 生产中
```

测法（**只读时只看，不点**）：

1. 找一条处于 A 状态的单据，记下**哪些按钮是可点的**；
2. 再找一条处于 B 状态的，对比按钮集合；
3. 如果"已审核"和"草稿"的按钮一模一样 → 状态没控制界面，基本可以判缺陷；
4. 如果同一个按钮在两种状态下都能点 → 至少是"待确认"（有些系统允许管理员强制）。

最典型的三种病：**状态能回退**（已完工又变回生产中）、**跳状态**（没下达就能报工）、**状态与数据不一致**（状态写着已完工，完工数量是 0）。

## 5. 行业特有的九类缺陷

通用 Web 缺陷（分页 0、按钮没反应）第 2 章已经讲了。下面这些**只有工业系统才会犯**，也最容易被漏掉。

### 5.1 单位换算错
- 现象：库存 1 吨，领料 500 千克，扣完变成 0.5 吨（对）或 999.5 吨（错）。
- 怎么测：找一个有"基本单位/辅助单位"的物料，录一次跨单位数量，回读两边。
- 为什么严重：**账实不符**，直接影响采购和成本。

### 5.2 BOM 循环 / 自我引用
- 现象：A 由 B 组成，B 又由 A 组成；或 A 的 BOM 里有 A。
- 怎么测：新建/查看 BOM 树，展开看有没有回到自己。只读时看"展开层级"是否有环。
- 后果：MRP 展开死循环，计划跑不出来。

### 5.3 超领 / 负库存
- 现象：库存 10，能领 100；领完库存显示 -90。
- 怎么测：找一个库存很小的物料，看领料数量输入框有没有上限校验（**只读时看提示文案和必填标记**）。
- 后果：账面负数，月底对不上。

### 5.4 重复报工 / 重复入库
- 现象：同一工序点两次"报工"，产量翻倍。
- 怎么测：看同一工单同一工序是否有重复记录；接口是否有幂等键。
- 后果：虚增产量，绩效和成本全错。

### 5.5 批次追溯断链
- 现象：成品批次能查到用了哪些原料，但原料批次查不到做成了哪些成品。
- 怎么测：双向查一次（正查 + 反查），看两边条数是否对得上。
- 后果：出了质量问题，召回范围说不清。

### 5.6 时间倒挂 / 时区错
- 现象：报工时间比开机时间早 8 小时（UTC 没转本地）；或完工日期早于开工。
- 怎么测：比较同一单据内多个时间字段，注意看有没有 `T00:00:00Z` 这种。
- 后果：OEE、工时统计全错。

### 5.7 状态机被绕过
- 现象：未审核的工单能直接报工；已关闭的工单还能改。
- 怎么测：找不同状态的单据，看按钮可用性是否随状态变。**只读时只看按钮灰不灰，不点。**
- 后果：流程失控，审计过不了。

### 5.8 主数据一物多码 / 多物一码
- 现象：同一个螺栓有两个编码；或两个不同物料共用一个编码。
- 怎么测：按名称/规格搜，看结果里有没有重复；按编码搜，看名称是否唯一。
- 后果：库存分散、采购重复、报表失真。

### 5.9 权限越界
- 现象：普通工人能看到成本价；跨车间能改别人工单。
- 怎么测：用不同角色登录（需要客户给账号），比对同一页面的按钮和数据范围。
- 后果：数据泄露、越权操作。

## 6. 小白提问清单

看不懂的页面，照着问。**问对人，比猜一天快。**

### 问客户（业务方）
1. 这个页面平时谁用？班组长、计划员还是仓管？
2. 这一步做完，下一道工序在哪个页面能看到？
3. 这个数字（指着一个字段）是从哪来的？手工填还是上游带过来？
4. 如果填错了，能改吗？谁能改？
5. 月底对账时，你们用哪个报表？和这个页面的数对得上吗？
6. 有没有"必须审核后才能往下走"的规定？
7. 哪些操作是**绝对不能**在测试环境做的？（这句话一定要问）

### 问页面（自己看）
1. 表头有没有"共 N 条"？和表格行数、导出条数对得上吗？
2. 有没有主子表？明细加起来等于表头吗？
3. 同一张单据里，几个时间字段的先后顺序合理吗？
4. 状态字段有几种值？按钮可用性和状态匹配吗？
5. 数量字段有没有单位？单位能不能改？改了数量变不变？
6. 有没有"审核/反审核""下达/撤销"这类成对按钮？点了会不会回退？
7. 空值、0、负数，页面分别怎么显示？（0 显示成空是常见坑）

## 7. 术语表（中英对照 + 大白话）

| 术语 | 英文/缩写 | 大白话 |
|---|---|---|
| 物料 | Material / Item | 一个东西的统称，包括原料、半成品、成品 |
| 物料主数据 | Material Master | 物料的"身份证"，全厂共用一份 |
| BOM | Bill of Materials | 做一件成品需要哪些料、各多少 |
| 工艺路线 | Routing | 按什么顺序、在哪个工位做 |
| 工作中心 | Work Center | 干活的地方，可以是机台、产线、工段 |
| 生产订单 | Production Order / Work Order | 一张"做多少、什么时候做完"的任务单 |
| 工单 | Work Order | 常和"生产订单"混用，有的系统里工单是订单的子集 |
| 工序 | Operation | 工艺路线上的一步，比如"粗车→精车→检验" |
| 派工 | Dispatching | 把工序分给具体的人/班组/设备 |
| 报工 | Production Reporting | 报告"我干了多少、废了多少、用了多久" |
| 在制品 | WIP (Work In Process) | 已经投料、还没变成成品的部分 |
| 领料 | Material Issue | 从仓库把料领到线上 |
| 退料 | Material Return | 没用完的料退回仓库 |
| 批次 | Batch / Lot | 一次投料/一次生产出来的一批，追溯的最小单位 |
| 追溯 | Traceability | 从成品查原料（反查），或从原料查成品（正查） |
| 首件检验 | First Article Inspection | 开工后先做一件送检，合格才批量做 |
| 不合格品 | Nonconforming Product | 检验没通过的产品，要隔离/返修/报废 |
| 让步接收 | Concession / Deviation | 不合格但勉强能用，需要特批 |
| 报废 | Scrap | 彻底不能用了 |
| 返修 | Rework | 修一修还能用 |
| 齐套 | Kit / Shortage Check | 料够不够做这一单 |
| MRP | Material Requirements Planning | 算"要买多少料、什么时候买" |
| OEE | Overall Equipment Effectiveness | 设备综合效率 = 时间×性能×合格率 |
| 节拍 | Cycle Time / Takt Time | 做一件要多久 / 多久必须出一件 |
| 线边仓 | Line-side Warehouse | 车间里临时放料的地方 |
| 库位 | Bin / Location | 仓库里的具体格子 |
| 安全库存 | Safety Stock | 低于这个数就该补货了 |
| 呆滞料 | Slow-moving / Obsolete | 很久没动过的料 |
| 主数据 | Master Data | 全厂共用、改动影响面很大的基础数据（物料、BOM、工艺、供应商） |

## 8. 把业务判断写进报告：三种口径

业务问题最怕"我觉得不合理"。报告里只用这三种说法：

| 口径 | 什么时候用 | 写法 |
|---|---|---|
| **确定错误** | 违反第 4 节的不变量，或同一记录内部自相矛盾 | "同一工单：投入 100、合格 80、报废 5、在制 0，差 15 无去向。" |
| **待业务确认** | 规则依赖于客户的实际做法，你不能替他们定 | "综合查询 2334 条、分类查询 826 条。已证实 826 是 2334 的子集；差的 1508 条是否应归入分类树，需业务确认口径。" |
| **观察项** | 不影响正确性，但可能影响效率/体验 | "报工页保存后无任何提示，需刷新才能看到结果。" |

**不要写**：
- ❌ "这里逻辑不对"（哪条逻辑？）
- ❌ "建议重做一版"（越界）
- ❌ "按行业惯例应该……"（你不是甲方）

**要写**：
- ✅ "违反数量守恒：……"
- ✅ "同一页面两个入口对同一个总量给出 2334 / 826，差 1508 条。"
- ✅ "修复方向：重置后触发一次默认查询。"（一句话，不展开设计）

## 9. 一页速查（打印出来贴屏幕）

```
① 这页属于哪个对象？  物料 / BOM / 工艺 / 工单 / 报工 / 库存 / 质检 / 追溯
② 这页的数字该满足哪条不变量？
   数量守恒 · 不超计划 · 时间不倒流 · 状态单向 · 已审核不可改
   唯一性 · 引用完整 · 明细=表头 · 单位一致 · 口径一致
③ 我算过了吗？      自己加一遍，别信页面上的合计
④ 我换个入口看过吗？ 列表 / 导出 / 看板 / 接口，四处对一次
⑤ 我能说清"对现场意味着什么"吗？
   说不清 → 写"待业务确认"，别写"缺陷"
```

## 附：离散制造 vs 流程制造（一句话区分）

- **离散制造**（汽车、电子、机械）：一件一件装配，按"个"数，BOM 是零件清单，工单可以拆工序。MOM 的主战场。
- **流程制造**（化工、食品、水泥）：一锅一锅反应，按"吨/升"算，配方代替 BOM，批次和效期是命门。

看到"配方/批次/效期/罐"这些词，按流程制造理解；看到"工序/工位/装配/件"，按离散制造理解。**两套的数量校验逻辑不一样**，别拿离散的"不超计划"去套流程的"按批次投料"。
