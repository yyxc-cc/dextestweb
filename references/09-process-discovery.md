# 09 · 流程逆向梳理：从"这个 app 管什么"到"数据怎么流"

> 解决的问题：**不知道系统该怎么用，就只能测"按钮能不能点"。**
> 这一篇给一套固定五步法——先定位功能，再去外部取证，再和同行对照，再还原数据流转，最后写成从零到一的编号步骤。
>
> 与其余章节的分工：
> `04-industry.md` = 业务概念与不变量；`05-mom-checks.md` = 单页检查点；
> `08-manufacturing-prompts.md` = 环节级提示模板；**本篇 = 遇到不认识的模块，如何把它"逆向拆明白"**。
>
> 所有示例为占位（`PL-001` / `P-001` / `BOM V1.0`），必须按被测系统实际核对，不得当成结论。

---

## 1. 什么时候必须走这套流程

满足任意一条就走，不要凭直觉直接开测：

- 第一次接触这个系统，或第一次进这个模块；
- 页面有一堆入口，但说不清"先做哪个、后做哪个"；
- 建完数据在列表里看不到，或前端页面查不到，但接口有返回；
- 客户提到"发布/生效/启用/审核"这类词，但界面上找不到明显按钮；
- 要给别人写操作步骤（实施、培训、验收文档），不能写错顺序。

**产出定位**：这套流程的产物不是"测试结论"，而是**一条能照着走通的线路**（编号步骤 + 数据流向 + 前置条件）。有了它，后面的缺陷判断才有基准。

---

## 2. 五步法（强制顺序，不许跳）

| 步 | 名称 | 一句话动作 | 主要产出 | 完成判据 |
|---|---|---|---|---|
| 1 | 功能定位 | 这块界面叫什么、归谁管、负责什么、不负责什么 | 一句话定位 + 角色清单 + 边界 | 能说出"它不负责什么" |
| 2 | 外部取证 | 拿功能名去各大平台检索 | 来源记录表（≥ 3 类来源） | 至少 3 类来源交叉印证 |
| 3 | 同行对照 | 同行在同一环节怎么做 | 相同点 / 差异点 / 本地支持程度 | 差异点都能标注"本地是否支持" |
| 4 | 数据流转还原 | 数据从谁创建、落到哪个对象、什么状态才对可见 | 流转图 + 状态门槛清单 | 能画出"创建 → 生效 → 可见"的完整链 |
| 5 | 从零编号步骤 | 写 Step 1…N，每步带输入/操作/状态变化/不做的后果 | 编号步骤表 + 整体线路图 | 编号与流程图节点一一对应 |

### 第 1 步 · 功能定位

**动作**：

1. 从界面取三个事实：菜单路径、页面标题、主要按钮（只读，不点）。
2. 用 `snap.js --verbose` 拿到页签/字段/列，判断它维护的是哪类对象（物料？BOM？工单？）。
3. 写一句话定位：`<模块名> 负责 <对象> 的 <哪一段生命周期>`。
4. 写边界：它**不负责**什么（不负责成本核算 / 不负责审批 / 不负责出库）。
5. 列角色：这个页面平时谁用（计划员 / 工艺员 / 仓管 / 质检），只列能验证的。

**产出**：一页《功能定位》

```
模块：基础数据 › 产品管理（占位）
定位：负责产品主数据的建立与发布，不负责 BOM 结构与工单执行
角色：工艺员（建）、技术主管（审）、计划员（引用）
边界：不做版本审批后的自动下发；不负责与 ERP 同步（同步在接口层）
```

**完成判据**：能把"它负责什么"和"它不负责什么"各说一句，且都有页面证据（菜单、字段、按钮）。

**常见错法**：把"模块名"当"功能"（"资源管理"不等于"物料主数据"，见 `04-industry.md` 3 节的物料 vs 资源）。

### 第 2 步 · 外部取证（至少 3 类来源）

**为什么必须做**：你不在这个行业里，靠猜会写出"应该是……"这种经不起追问的句子。外部资料给你两样东西：**通用流程顺序** 和 **判断基准**。

**来源矩阵（至少取 3 类，且要跨类型）**：

| 类型 | 去哪找 | 搜什么词 | 能拿到什么 |
|---|---|---|---|
| 官方文档 / 帮助中心 | 厂商官网、产品手册 PDF、在线帮助 | `<产品名> + 产品管理 + 发布` | 最权威的字段含义与状态定义 |
| 视频教程 | B 站、抖音、视频号、厂商培训课 | `<产品名> + 建模 + 教程` / `MOM 产品主数据` | 实际操作顺序（先点哪、后点哪） |
| 技术文章 | CSDN、知乎、公众号、博客园 | `<模块> + 数据表 / 状态机 / 踩坑` | 表结构、常见坑、隐式规则 |
| 厂商实施案例 | 行业方案白皮书、招标文件、实施总结 | `<行业> + MES 实施 + 主数据` | 上线时的真实约束（谁先建、谁审批） |
| 同行产品 | 用友 / 金蝶 / SAP / 鼎捷 / 西门子 等的同类模块 | `SAP 物料主数据 发布` / `金蝶 产品 启用` | 同环节的标准做法，用来做对照 |

**每条都要落成一行记录**：

| 来源类型 | 出处（标题/链接/UP 主） | 关键结论（一句话） | 与本地实际是否一致 | 置信度 |
|---|---|---|---|---|
| 官方文档 | 《XX 产品手册》第 N 节 | 产品需"发布"后才可被下游引用 | 一致 | 高 |
| 视频教程 | B 站《XX 建 BOM 全流程》 | 顺序是 产品线 → 产品 → BOM | 部分一致（本地缺审核步） | 中 |
| 同行产品 | SAP 物料主数据视图 | 主数据按视图分部门维护 | 不一致（本地单视图） | 中 |

**完成判据**：≥ 3 类来源，且**至少有 1 条官方或同行产品级来源**。全是同一类博客文章不算交叉印证。

**检索不到怎么办**：写"未找到可靠资料"，并给出《待确认问题清单》（见第 7 节）。**不许编造行业惯例。**

### 第 3 步 · 同行对照

**动作**：把第 2 步的资料按"同一个环节"对齐，逐项比这五样：

1. 字段叫法（产品 / 物料 / 品号；BOM / 配方 / 用料表）
2. 必填约束（编码、单位、分类是不是必填）
3. 审批环节（有没有审核、几级、谁审）
4. 状态机（草稿→审核→发布→生效→停用，允许回退吗）
5. 版本与变更（有没有版本号、生效日期、变更单 ECN）

**输出格式**（差异必须标"本地是否支持"）：

| 环节 | 本地系统 | 同行做法（来源） | 相同 / 差异 | 本地是否支持 |
|---|---|---|---|---|
| 产品建立 | 建完直接可查（占位） | SAP：建完为"未发布"，需发布（官方文档） | 差异 | 不支持（疑似缺发布态） |
| 发布/生效 | 未见发布按钮 | 金蝶：启用后才可选（帮助中心） | 差异 | 待验证 |
| BOM 版本 | 显示 V1.0 | 用友：版本 + 生效日期（实施案例） | 部分相同 | 支持版本，缺生效日期 |

**完成判据**：差异点全部有"本地是否支持"结论；不能确定的写"待验证"，不要写"肯定没有"。

### 第 4 步 · 数据流转还原

**要回答四个问题**：

1. **谁创建**：哪个角色、哪个页面、哪个按钮（精确到按钮文案）。
2. **落到哪**：哪个对象/表/接口（能从接口响应、字段名、详情页 URL 反推；有库权限再看表）。
3. **什么状态才可见**：草稿 / 待审 / 已发布 / 已生效——**哪一步之后才会出现在列表、下拉框、前台、下游模块**。
4. **谁依赖它**：BOM 引用它、工单引用 BOM、报表统计它——下游断在哪，就是流程断在哪。

**产出**：流转图（Mermaid 或 ASCII），节点 = 对象或状态，边 = 动作。示例见第 5 节。

**完成判据**：能指着图中任意一个节点说出"它由谁写、被谁读、卡在哪个状态"。

### 第 5 步 · 从零到一编号步骤

**写法规则**：

- 编号用 `Step 1…N`，**与流程图节点编号一一对应**，不许一个图两套号；
- 每步四栏：**输入 / 操作 / 状态变化 / 不做会怎样**；
- "不做会怎样"必须写具体后果（"不在列表出现""下游选不到""保存报错但无提示"）；
- 步与步之间有依赖的，显式写"前置：Step N"；
- 可选项（如跳过审核）标"可选"，不要混在必经步骤里。

**产出**：编号步骤表 + 整体线路图（两者编号一致）。

## 3. 隐性前置条件清单（最容易漏的那些）

这类约束的特征：**界面上看不出来，文档里也不显眼，但不做就卡住**。看到"我建了但看不到""下拉框是空的""保存时才报错"，先来这张表对。

### 3.1 状态与可见性（最高频）

| 症状 | 真实原因 | 验证方法 |
|---|---|---|
| 新建的产品/物料在列表里查不到 | 处于"草稿/未生效"，需要**发布 / 启用 / 审核通过**才进正式库 | 新建后看详情页状态字段；切"全部/草稿"页签再查；对比接口是否返回该记录 |
| 下拉框里选不到刚建的对象 | 下拉只查"已发布/已生效"数据 | 用同一对象在列表页确认状态；换一个已发布对象试选 |
| 前台/门户/APP 看不到 | 后台发布 ≠ 前台展示，另有"上架/同步/推送"动作 | 查是否有同步日志/同步按钮；看前台请求的接口过滤条件 |
| 已发布的数据还是不在统计报表里 | 报表按"生效日期"或"期间"过滤，不是按发布时间 | 改生效日期到当前期间再看；核对报表口径说明 |
| 批量导入后"成功 N 条"但一条都看不到 | 导入只写暂存表，需要"提交/确认/审核" | 找导入批次记录/暂存表；看是否有二次确认按钮 |

### 3.2 主数据引用（不先建就没得选）

| 症状 | 真实原因 | 验证方法 |
|---|---|---|
| 建产品时"产品线"必填但下拉为空 | 产品线还没建，或未启用 | 先去产品线模块核对；再看该下拉的接口返回条数 |
| 建 BOM 时子件选不到 | 物料未建、已停用、或未发布 | 按编码精确查物料详情页状态 |
| 建工单时工作中心/工序为空 | 工艺路线未建或未生效 | 查工艺路线版本与生效日期 |
| 单位、库位、供应商为空的字段能保存 | 主数据缺失但校验只在保存时触发 | 只读时看新建弹窗必填标记（`*`）与保存按钮状态 |

**最小前置链（离散制造常见）**：
`计量单位 → 物料分类 → 物料/产品 → 产品线 → 工艺路线/工序 → 工作中心 → BOM → 工单`
缺任一环，后面都选不到。**这条链本身就是一张"先建什么"的顺序表。**

### 3.3 校验与必填（界面不标红，保存才报）

| 症状 | 真实原因 | 验证方法 |
|---|---|---|
| 页面没有 `*`，保存却报"必填" | 前端必填标记与后端校验不一致 | 只读时点开新建弹窗，逐个字段看标记；再看保存时报错字段 |
| 编码能重复输入 | 唯一性校验在保存时做，且可能只校验同分类内 | 用同一编码建两次（**只在获准写操作时**）；只读时看是否有"重复校验"提示文案 |
| 长文本/特殊字符保存失败 | 字段长度或字符集限制未提示 | 看报错原文；记录字段类型 |
| 导入模板报"格式错误"但不知错在哪 | 模板行级校验不返回行号 | 看导入结果文件/错误列表 |

### 3.4 权限与组织维度（"看不到"≠"没数据"）

| 症状 | 真实原因 | 验证方法 |
|---|---|---|
| 同事能看到，我看不到 | 数据权限按组织/工厂/车间隔离 | 换同角色不同组织账号对比；看列表请求是否带 orgId |
| 菜单根本不显示 | 角色未授权该菜单 | 用管理员账号看菜单是否存在；记录账号角色 |
| 能看不能改 | 按钮级权限 | 对比同页面不同角色的按钮集合 |
| 数据条数比别人少 | 数据范围过滤（本人/本班组） | 用"全部"数据账号核对总数 |

### 3.5 版本与变更（已发布不能随便改）

| 症状 | 真实原因 | 验证方法 |
|---|---|---|
| 已发布的产品改不了 | 需要"变更单/ECN"或"反审核"才能改 | 看是否有"变更/修订/升版"按钮；查变更单模块 |
| 改了 BOM 但工单还用旧料 | 工单锁定版本；或新版本未生效 | 对比工单引用的版本号与当前生效版本 |
| 同一对象两个"生效"版本 | 生效日期/失效日期未闭环 | 查版本列表的生效与失效日期 |
| 删除报 500 / 无反应 | 被下游引用（引用完整性） | 去下游模块搜该编码，确认引用关系 |

### 3.6 时间、批量与异步

| 症状 | 真实原因 | 验证方法 |
|---|---|---|
| 提交后立刻查不到，过几分钟才有 | 异步任务/消息队列，界面没提示"处理中" | 连续观察 3 次，记时间差；找"任务/日志"页 |
| 批量操作只成功一部分 | 部分行校验失败，整体不回滚 | 看结果页的成功/失败条数与原因列 |
| 日期选择器默认值导致查不到数据 | 默认区间是"本月"或"今天" | 清空日期再查一次（只读允许） |
| 时间差 8 小时 | UTC 与本地时区混用 | 对比接口时间戳与页面显示 |

## 4. 端到端示例：产品线 → 产品 → 发布 → BOM → 工单引用

> 场景：从零开始，先把"建什么、什么时候才可见、什么时候才能被引用"走通。
> **示例为占位骨架，字段名以被测系统为准。**

### 4.1 整体线路图（编号与 4.2 步骤表一一对应）

```mermaid
flowchart LR
  S1["1 建产品线<br/>PL-001<br/>状态:草稿"] --> S2["2 建产品<br/>P-001<br/>状态:草稿"]
  S2 --> S3["3 提交审核<br/>状态:待审"]
  S3 --> S4["4 审核通过 + 发布<br/>状态:已发布"]
  S4 --> S5["5 列表/前台可见<br/>可被下游引用"]
  S5 --> S6["6 建 BOM<br/>BOM V1.0<br/>状态:草稿"]
  S6 --> S7["7 BOM 审核<br/>状态:待审"]
  S7 --> S8["8 BOM 生效<br/>生效日期:今天"]
  S8 --> S9["9 工单引用<br/>WO-001 取到 BOM"]
```

ASCII 版（贴到纯文本报告里用）：

```
[1 建产品线] ──▶ [2 建产品] ──▶ [3 提交审核] ──▶ [4 发布生效] ──▶ [5 可见/可引用]
                                                          │
                                                          ▼
[9 工单引用] ◀── [8 BOM 生效] ◀── [7 BOM 审核] ◀── [6 建 BOM]
```

### 4.2 编号步骤表

| # | 输入 | 操作 | 数据流向（谁创建 → 落到哪 → 什么状态） | 前置条件 | 产出物 | 不做会怎样 |
|---|---|---|---|---|---|---|
| 1 | 产品线编码 `PL-001`、名称（占位） | 产品线模块 → 新建 → 保存 | 工艺员 → `产品线` 对象 → **草稿** | 无 | 产品线记录 | 建产品时"产品线"下拉为空 |
| 2 | 产品编码 `P-001`、名称、单位、分类 | 产品管理 → 新建 → 选产品线 → 保存 | 工艺员 → `产品` 对象 → **草稿**（保守假设，需核对） | Step 1 完成且产品线可用 | 产品草稿 | 产品不能出现在任何选择器里 |
| 3 | 草稿产品 | 提交审核（或"送审"） | 工艺员 → 状态 **草稿 → 待审** | Step 2 完成；必填齐全 | 待审记录 + 审核任务 | 后续无审批人可审，流程停住 |
| 4 | 待审产品 | 技术主管审核通过 → **发布/启用** | 审核人 → 状态 **待审 → 已发布**；发布时间落库 | 审核角色账号 | 已发布产品 | 列表查不到、BOM 里选不到（**这是最容易被漏的一步**） |
| 5 | 已发布产品 | 打开产品列表 / 前台/门户 | 已发布 → 被列表查询接口读到 → 对外可见 | Step 4 完成 | 可见性证据（截图 + 接口） | 你会误判成"创建失败" |
| 6 | 已发布产品 `P-001`、子件物料、用量、版本 `V1.0` | BOM 模块 → 新建 → 加行 → 保存 | 工艺员 → `BOM` 对象 → **草稿**；子件引用物料主数据 | Step 5 完成；子件物料已发布 | BOM 草稿 | BOM 列表不出现；工单选不到 BOM |
| 7 | BOM 草稿 | 提交审核 | 工艺员 → **草稿 → 待审** | Step 6 完成；用量>0 | 待审 BOM | 无法生效，工单仍用旧版 |
| 8 | 待审 BOM | 审核通过 → 设 **生效日期** | 审核人 → **待审 → 已生效**；写生效日期 | 版本号唯一；无冲突生效版本 | 生效 BOM `V1.0` | 工单取到空 BOM 或旧 BOM |
| 9 | 生产订单 `WO-001`、产品 `P-001`、数量 | 工单模块 → 新建 → 选产品 → 系统带出 BOM/工艺 | 计划员 → `工单` 对象 → 引用 `BOM V1.0` + `工艺路线` | Step 8 完成 | 工单草稿（含 BOM 快照） | 工单建不出，或 BOM 明细为空 |

### 4.3 状态门槛（必须画在图上，不能只写在正文）

| 对象 | 状态序列 | 进入"可见"的门槛动作 | 谁有权做 | 能不能回退 |
|---|---|---|---|---|
| 产品线 `PL-001` | 草稿 → 启用 → 停用 | **启用** | 工艺员/主管 | 待核对 |
| 产品 `P-001` | 草稿 → 待审 → 已发布 → 停用 | **审核通过 + 发布** | 技术主管 | 待核对 |
| BOM `V1.0` | 草稿 → 待审 → 已生效 → 失效 | **审核通过 + 生效日期到达** | 技术主管 | 待核对 |
| 工单 `WO-001` | 草稿 → 已下达 → 生产中 → 已完工 | **下达** | 计划员 | 待核对 |

> 关键判断：**"保存成功"≠"已发布"≠"已生效"≠"可见"**。这四件事在多数系统里是四个不同状态，混淆就会写出错的结论。

## 5. 反"瞎提示"四条纪律（硬性）

1. **每条流程结论必须可溯源。**
   - 可指到**外部来源**（官方文档 / 视频 / 同行案例，带标题或链接）；或
   - 可指到**系统内证据**（字段名、状态值、接口返回、日志、表结构）。
   - 两者都没有的，一律写"待验证"，**不允许写成肯定句**。

2. **检索不到就明说。**
   写"未找到可靠资料"，然后给《待确认问题清单》。编造"行业惯例"是这类工作的头号事故来源。

3. **同名不等于同义，先统一口径。**
   "产品 vs 物料"、"BOM vs 配方"、"工单 vs 生产订单"、"发布 vs 生效"在不同厂商语义不同。
   写报告前先定一段"本文口径"：`本文"产品"指……，"发布"指……`。口径不统一，后面所有结论都会歪。

4. **区分三种确定度，措辞必须跟着变。**

| 确定度 | 触发条件 | 允许的写法 |
|---|---|---|
| 确定 | 有系统内证据（字段/状态/接口）或官方文档明示 | "已发布状态未提供发布按钮" |
| 待验证 | 只有同行做法或单一来源 | "同行普遍需发布后才可引用；本地未找到发布入口，**待验证**" |
| 未找到资料 | 检索无可靠结果 | "未找到可靠资料；建议向实施顾问确认以下 3 个问题：…" |
