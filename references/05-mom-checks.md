# 05 · MOM 只读快检表：一页一页照着对

> 配合 `04-industry.md` 用。这里不讲概念，只给**能在页面上直接看出来的检查点**。
> 全部只读：只查询、切页签、开弹窗看字段、翻页，不点保存/新增/删除/提交。
> 每条都写了"看什么 / 违反哪条不变量 / 证据怎么留"。

---

## 用法（3 分钟上手）

1. 打开一页，先用 `snap.js` 把页签/按钮/字段/列/分页列出来；
2. 在下表找到对应分组，从上往下对；
3. 命中问题的，记下**页面读数 + 接口返回 + 截图/视频标记**，三样齐了再写报告。

> 只读能发现的缺陷，约占业务类问题的一半。剩下的一半必须写数据才能暴露——**列进"未覆盖"，
> 不要为了凑数去点保存**。

## A. 物料主数据 / 资源管理

| # | 检查点 | 怎么看 | 违反 |
|---|---|---|---|
| A1 | 编码唯一 | 用同一个编码再查一次；按名称搜，看是否一物多码 | 唯一性 |
| A2 | 必填项真的是必填 | 新建弹窗里，编码/名称/单位有没有 `*`；没有就是"能建出空壳物料" | 唯一性/完整性 |
| A3 | 单位不为空 | 列表里有没有空的"基本计量单位" | 完整性 |
| A4 | 分类挂在末级 | 分类树展开，物料挂的是叶子还是中间节点 | 引用完整性 |
| A5 | 停用/作废物料不参与业务 | 筛选"状态=停用"，看是否还能被领料/报工选到 | 状态单向 |
| A6 | 列表总数 = 分页总数 = 导出条数 | 三处各读一次 | 口径一致 |
| A7 | 两个入口口径 | 如"综合查询"vs"分类查询"，先证明包含关系 | 口径一致 |

## B. BOM / 配方

| # | 检查点 | 怎么看 | 违反 |
|---|---|---|---|
| B1 | 无循环 | 逐层展开，看子件是否回到父件 | 引用完整性 |
| B2 | 用量 > 0 | 扫一遍用量列，有没有 0 或负数 | 数量守恒 |
| B3 | 版本唯一生效 | 同一父件是否同时有两个"生效"版本 | 唯一性 |
| B4 | 子件存在且未停用 | 子件编码能否在物料页查到 | 引用完整性 |
| B5 | 损耗率合理 | 损耗率 > 100% 时应能解释（有些工艺确实如此） | 待确认 |

## C. 工艺路线 / 工作中心

| # | 检查点 | 怎么看 | 违反 |
|---|---|---|---|
| C1 | 工序号不重复、能不连续但有序 | 看工序列表 | 唯一性 |
| C2 | 工作中心存在 | 工序引用的工作中心能否在台账里查到 | 引用完整性 |
| C3 | 工时不为 0 | 准备/单件工时全 0 → 排产必崩 | 完整性 |
| C4 | 路线与工单一致 | 工单详情里的工序 vs 路线定义 | 口径一致 |

## D. 生产订单 / 工单

| # | 检查点 | 怎么看 | 违反 |
|---|---|---|---|
| D1 | 计划数量 ≥ 已投数量 | 列表两列直接比 | 不能超计划 |
| D2 | 计划开始 ≤ 计划结束 | 两列直接比 | 时间不倒流 |
| D3 | 状态与按钮匹配 | 已完工的单还能点"报工"？未下达能"开工"？ | 状态单向 |
| D4 | 状态与数据匹配 | 状态=已完工，完工数量却是 0 | 状态一致 |
| D5 | 同一订单不重复 | 按订单号搜，是否两条 | 唯一性 |
| D6 | 日期格式统一 | 有没有 `2026-10-30` 和 `2026/10/30` 混用 | 观察项 |

## E. 报工 / 产出

| # | 检查点 | 怎么看 | 违反 |
|---|---|---|---|
| E1 | 投入 = 合格 + 报废 + 在制 | 拿一张工单自己算 | 数量守恒 |
| E2 | 报工时间 ≥ 开工时间 | 两个时间字段比 | 时间不倒流 |
| E3 | 同一工序不重复报工 | 报工记录按工序聚合，看有没有两条同一时刻 | 唯一性 |
| E4 | 累计报工 ≤ 计划 | 多翻几页加总 | 不能超计划 |
| E5 | 报废/返修有去向 | 报废数 > 0 时，有没有报废单/原因 | 完整性 |

## F. 领料 / 库存

| # | 检查点 | 怎么看 | 违反 |
|---|---|---|---|
| F1 | 库存不为负 | 筛选库存 < 0（有的系统能筛） | 数量守恒 |

## G. 质检 / 不合格品

| # | 检查点 | 怎么看 | 违反 |

## 写操作才会暴露的（列出来，但不做）

这些必须建单/改数才能验，只读阶段**只记录"未覆盖"**：

- 保存失败是否回滚（最严重的一类，见 `02-evidence.md`）
- 并发/重复提交是否幂等
- 审核后是否还能改
- 删除被引用对象是否拦截
- 权限：不同角色看到的按钮/数据范围
- 导入模板的容错（空行、错格式、重复编码）
- 打印/导出与页面是否一致

> 报告里的写法：**"未覆盖：需要写入权限，已向客户申请/客户未提供账号"**，
> 而不是假装测过。

## 附：完整算例（把不变量用起来）

> 真实案例：计划 4 件，系统里"已投数量"变成 33。新手看到只会说"数不对"，
> 按下面的顺序走，你能说清"哪一步、加了多少、为什么"。

**背景**：订单 `PO_202610120176`，产品轮毂，计划 4 件，初始已投 1 件。

**第 1 步：先立等式**

```
计划 4 = 已投 1 + 未投 3        ✅ 初始状态自洽
```

**第 2 步：走一次"建码"（写操作，需授权）**

操作：物料建码 → 勾选订单 → 数量 4 → 生成 4 个编码 → 保存
结果：顶部红字"剩余可投数量为 3.0，请检查！"，保存被拦截。

**第 3 步：回列表读数**

```
计划 4，已投 1 → 刷新后已投 5
```

**第 4 步：再重复两次**

```
已投 5 → 9 → 13     每次 +4
```

**第 5 步：换一个入口验证**

- 列表页：已投 33
- 详情/接口：`quantityInvested = 33`
- 编码表：新增 0 条

**结论（可直接写进报告）**：

> 保存被校验拦截时，前端已把"已投数量"写进内存/草稿，后端未回滚；每次失败 +4，7 次后
> 计划 4 件的订单显示已投 33 件，而编码表 0 条新增。违反"数量守恒"与"失败应回滚"。

**为什么这是 P0**：账实不符，且不可逆——操作者以为没成功，实际每次都改了数。

**证据组合**：

| 证据 | 内容 |
|---|---|
| 数值序列 | `1 → 5 → 9 → 13 … 33`（每一步截图） |
| 接口/详情 | `quantityInvested = 33` |
| 明细反证 | 编码表 0 条新增 |
| 视频 | 一次完整"保存被拦截 → 刷新 → 数字变大" |

**换成你测的系统**：先找"计划/已投/完成/报废"这几个数，立一个等式，再走一遍主流程，
看等式什么时候破。破了就是缺陷；没破，你就得到了一条"这段是好的"的对照证据。
