# 08 · 工艺生产企业管理流程提示：每个环节问什么、核对什么、容易漏什么

> 这一章解决"**会测页面，但不会测流程**"。
> `04-industry.md` 给概念和不变量，`05-mom-checks.md` 给单页检查点；
> 这一章给**环节级的提示模板**：把一段业务管理流程，翻译成"问客户的问题 + 页面该核对的等式 + 最容易漏的点"。
>
> 用法：被测系统是制造企业（工艺 / 生产 / 物料 / 质量 / 设备 / 委外 / 成本）时，先找到对应环节，复制模板，填占位值，再开始只读核对。
> 全部示例数据为占位（`PO_样例-0001` / `物料 M-0001` / `工序 OP10`），不要当成真实企业数据。

---

## 0. 通用提示骨架（所有环节都套这个）

任何一个环节的提示词，都按这六段写，缺一段模型就会自由发挥：

```
【身份】你是一名只做只读的外测工程师，被测对象是一个制造企业的 Web 系统（不是这个系统的开发者）。
【任务】只核对"<环节名>"这一段流程，不扩展到其他模块。
【约束】不点新增/保存/删除/审核/导入；不判"应该怎么设计"；不确定的业务规则标"待业务确认"。
【核对项】1) … 2) … 3) …（写具体的字段、等式、状态组合）
【产出】一张表：检查项 / 页面读数 / 通过·异常·待确认 / 违反的不变量编号 / 证据文件名。
【何时停】遇到 <写操作需求 / 口径冲突 / 数据缺口> 就停下来列问题，不要继续猜。
```

三条通用纪律：

1. **一个环节只问 3~5 个问题**。问太多，客户答不上来，你也会忘。
2. **每个环节都要"立等式"**：数量、时间、状态三者至少立一个，能算就别靠眼。
3. **环节之间要串**：单环节对得上、串起来对不上，才是最有价值的那类缺陷（见第 11 节）。

## 1. 工艺路线与工序管理

**系统里的样子**：工艺路线（Routing）→ 工序（Operation）→ 工作中心（Work Center）→ 工时/工序参数；常与"工艺版本""替代工序""跳序"放在一起。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 这条路线由谁维护、改了要不要走审批？ | 工序号唯一、有序（可跳号但不可重号） | 只看主路线，漏了"替代路线/返修路线" |
| 有没有"同一物料多版本路线"？版本怎么生效？ | 同一物料当前**只有一条生效路线** | 版本生效日期为空，却显示"生效" |
| 哪些工序必须首检？ | 首检工序在工序表里有标记，且与检验模块一致 | 工序标记了首检，检验页里却查不到对应检验项 |
| 标准工时谁定、多久更新一次？ | 准备工时/单件工时 ≠ 0（全 0 → 排产必崩） | 只查一个工序，没扫全表 |
| 有没有外协工序（委外）？ | 外协工序的工作中心指向"外协供应商"而不是内部机台 | 外协标记与委外单不一致（见第 9 节） |

**立等式**：`路线总工时 ≈ Σ(各工序准备工时 + 单件工时 × 计划数)`。用一张工单反算，差得离谱就是工时口径问题。

**提示模板**：

```
【身份】只读外测工程师，被测系统为制造企业 MOM。
【任务】核对"工艺路线与工序管理"这一段。
【约束】只查列表/详情/页签，不点新增或保存。
【核对项】
1. 工序号是否唯一、是否有序（允许跳号，不允许重号或乱序）；
2. 每道工序引用的工作中心，能否在工作中心台账中查到且未停用；
3. 准备工时与单件工时是否存在 0 值（0 值会导致排产异常）；
4. 同一物料是否存在两条同时"生效"的工艺路线版本；
5. 标记"首检"的工序，能否在检验模块找到对应检验项；
6. 外协工序的归属是否指向外部供应商。
【产出】表格：工序号/工序名/工作中心/工时/异常点/违反不变量编号；对不上口径的写"待业务确认"。
【何时停】若发现需要新增路线才能验证版本切换，停下来，记为"未覆盖：需写权限"。
```

## 2. BOM / 物料清单

**系统里的样子**：BOM 头（父件 + 版本）→ BOM 行（子件 + 用量 + 损耗率 + 生效日期）；流程制造叫"配方"，按批次投料。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| BOM 有几层？最多展开几层？ | 逐层展开不回到父件（无环） | 只展开第一层就下结论"结构正常" |
| 用量是净用量还是含损耗？ | 用量 > 0；损耗率有明确含义 | 用量单位与物料基本单位不一致 |
| 替代料怎么配？什么时候生效？ | 替代料组里主料存在且未停用 | 替代料用量合计超过主料用量 |
| 版本切换时，在制工单用哪个版本？ | 老工单是否锁定老版本 | 只查"新单"，漏了在制单的版本漂移 |
| 有没有"虚拟件/phantom"？ | 虚拟件不生成库存、只展开 | 把虚拟件当实体物料查库存，得出"库存为 0 = 缺料" |

**立等式**：`父件用量 = Σ(子件用量 × (1 + 损耗率))`（口径需客户确认，含/不含损耗差别很大）。找一个能算的 BOM 自己加一遍。

**提示模板**：

```
【任务】核对"BOM / 物料清单"这一段，重点看结构正确性与版本生效。
【核对项】
1. 任取 3 个 BOM，逐层展开，确认没有循环引用（子件不会回到父件）；
2. 扫用量列，是否有 0 或负数；单位是否与物料基本单位一致；
3. 同一父件是否同时存在多个"生效"版本（应为唯一）；
4. 子件是否都存在且未停用（引用完整性）；
5. 抽 1 张在制工单，确认它引用的 BOM 版本与当前生效版本的关系（锁定/漂移）写清。
【产出】表格 + 一处"能自己算通"的算式（父子件用量合计），算不通的标"待业务确认"。
【何时停】若需新建 BOM 才能验证唯一性，停下来写"未覆盖"。
```

## 3. 生产计划与工单下达

**系统里的样子**：生产计划（MRP 结果/手工计划）→ 生产订单/工单 → 工序任务 → 派工/下达。字段：单号、物料、计划数、计划开完工、状态、优先级。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 计划是谁下的？能改几次？ | 计划数量被改小时是否有痕迹/审批 | 只看"当前值"，没看修改记录 |
| 工单必须下达才能报工吗？ | 未下达的工单不能开工/报工（状态单向） | 只看列表按钮，没进详情看工序状态 |
| 计划日期能不能早于今天？ | 计划开工 ≤ 计划完工 | 补单场景（允许倒填日期）——这是业务特例，别判 bug |
| 一单多工序怎么派？ | 派工的人/班组/设备真实存在且未停用 | 派给停机设备或已离职人员，系统是否拦 |
| 工单能不能拆/合并？ | 拆分后数量合计 = 原计划数 | 拆完没回写原单，两边数量都对不上 |

**立等式**：`计划数 = 已完工 + 在制 + 未开工`；`Σ(拆分工单计划数) = 原工单计划数`。

**提示模板**：

```
【任务】核对"生产计划与工单下达"这一段，重点是状态流转和数量一致性。
【核对项】
1. 找 3 张不同状态的工单（未下达/已下达/生产中），对比按钮可用性：状态与按钮是否匹配；
2. 是否存在"未下达却能开工/报工"的入口；
3. 计划数量 ≥ 已投数量 ≥ 已完工数量，逐个比；
4. 计划开始日期 ≤ 计划完工日期；实际开始是否晚于计划（可接受）但早于派工（异常）；
5. 若有拆分工单：拆分后数量合计是否等于原计划数。
【产出】表格：工单号/状态/计划数/已投/完工/异常点；状态与按钮不匹配的，附按钮清单。
【何时停】发现需要点"下达"才能继续验证，停下来申请写权限或记"未覆盖"。
```

## 4. 领料与投料

**系统里的样子**：领料单/发料单（按工单或按工序）→ 批次/库位 → 投料记录。常有"限额领料""超额审批""退料回冲"。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 领料按工单还是按工序？ | 领料单与工单/工序的引用关系能对上 | 按工序领料时，工序号为空也算"能领" |
| 超领要不要审批？谁批？ | 领料数 > BOM 用量 ×(1+损耗) 时有拦截或审批标记 | 只看有没有提示，没看是否真拦住 |
| 退料怎么回冲？ | 净领 = 领 − 退，且回写到工单成本 | 退料不回冲，账面上一直"已领" |
| 批次必须选吗？ | 批次管理物料在领料时必须带批次 | 批次为空也能保存（追溯必断） |
| 线边仓怎么管？ | 线边库存 = 已领 − 已投 − 已退 | 把线边库存当总库存，得出"库存虚高" |

**立等式**：`库存期末 = 期初 + 入库 − 领料 + 退料`；`工单已领 = Σ领料明细 − Σ退料明细`。

**提示模板**：

```
【任务】核对"领料与投料"，只读。
【核对项】
1. 抽 2 张领料单，确认其引用的工单/工序存在且状态允许领料；
2. 领料数量与 BOM 应耗量对比（BOM 用量 × 计划数 ×(1+损耗率)），超出的记"疑似超领"并看有无审批标记；
3. 批次管理物料：领料记录的批次是否为空；
4. 找一张有退料的单，核对净领是否等于 领 − 退；
5. 库存是否出现负数（能筛就筛，不能筛就看最小库存物料）。
【产出】表格 + 一条"期初/入库/领料/退料/期末"的算式核对结果。
【何时停】需要真实领料才能验证超领拦截时，停；写"未覆盖：需写权限"，不要代替客户点保存。
```

## 5. 报工与在制（WIP）

**系统里的样子**：报工单/产出申报（按工序）→ 合格数 / 不合格数 / 报废数 / 工时 / 班次；在制看板按工序汇总。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 报工按工序还是按工单？ | 报工记录能定位到工序号 | 只有工单级报工，工序级 WIP 全是估算 |
| 允许超报吗？上限多少？ | 累计报工 ≤ 计划数（超了要有提示） | 翻页只加了一页就下结论 |
| 报废要不要单独单据？ | 报废数 > 0 时有报废单/原因码 | 报废只在报工里填个数，没有去向 |
| 工时怎么来？刷卡还是手填？ | 工时合计 ≤ 班次时长；不与考勤冲突 | 一人同一时段两单（见 04 的派工冲突） |
| 在制怎么算？ | 在制 = 已投 − 合格 − 报废 − 已入库 | 分母用"计划数"而不是"已投"，等式必错 |

**立等式（最重要的一条）**：`投入 = 合格 + 报废 + 在制 + 返修在制`。这条对不上，直接按 `04-industry.md` 不变量第 1 条写缺陷。

**提示模板**：

```
【任务】核对"报工与在制"，只读，核心是数量守恒。
【核对项】
1. 取 2 张有报工记录的工单，逐个工序列出：投入 / 合格 / 不合格 / 报废 / 在制；
2. 自己算 投入 = 合格 + 报废 + 在制（有返修就单列），差额写清数值；
3. 同一工序是否有重复报工（同一时刻两条记录、或同批次重复提交）；
4. 累计报工数是否超过计划数；若超过，页面有没有提示；
5. 报工时间是否晚于开工时间、且不晚于当前时间（注意 UTC/本地时区差 8 小时）。
【产出】逐工序表 + 一条守恒等式结论；差额无去向的写"确定错误（违反数量守恒）"。
【何时停】若守恒差额需要查库/查上游才能解释，停下来列问题给客户，不要自行归因。
```

## 6. 质量检验与不合格品

**系统里的样子**：检验单（来料/首检/巡检/完工检）→ 检验项/判定 → 不合格品处理（返修/报废/让步接收/退货）。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 哪些工序必须检？检验不合格能不能往下走？ | 工序完成条件绑定检验合格 | 只看"有检验页"，没看"能不能绕过" |
| 抽样规则谁定？AQL 还是全检？ | 抽样数 ≤ 批数；判定与不合格数一致 | 判定=合格但不合格数 > 0（自相矛盾） |
| 让步接收谁批？有没有有效期？ | 让步接收单有审批人/单号/有效期 | 只有状态没有审批痕迹 |
| 不合格品去哪了？ | 返修/报废/退货三条去向都有单据 | 只改状态不给去向，等于"凭空消失" |
| 复检怎么触发？ | 返修后能再开一次检验 | 返修件直接回流下道，无复检记录 |

**立等式**：`检验批数 = 合格批 + 不合格批 + 让步接收批`；`不合格数 = 返修数 + 报废数 + 退货数 + 待处理数`。

**提示模板**：

```
【任务】核对"质量检验与不合格品处理"，只读。
【核对项】
1. 抽首检/巡检/完工检各 1 张单，检查检验项是否齐全、判定与数量是否自洽（判定合格但不合格数>0 属矛盾）；
2. 抽样数 ≤ 批数；抽样数与判定规则是否能对应；
3. 不合格品是否有明确去向（返修/报废/让步/退货），有无对应单据编号；
4. 让步接收是否有审批人与有效期；
5. 返修后是否有复检记录（无复检就回流 = 质量门失效）。
【产出】表格 + 每条不合格品的去向链（单号 → 状态 → 下游页面）。
【何时停】若需要点"判定"或"提交"才能验证审批流，停；写"未覆盖"并说明需要什么角色。
```

## 7. 物料变更 / 工程变更（ECN）

**系统里的样子**：变更申请（ECN/ECO）→ 影响评估（BOM/工艺/在制/库存）→ 审批 → 生效（切换时点 + 旧料处理）。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 变更走哪条审批链？几级？ | 变更单有状态机与审批记录 | 只有"已变更"状态，没有审批节点 |
| 生效是"立即"还是"按日期/按工单"？ | 生效日期与切换规则明确，且能查到 | 生效日期为空仍然当作已生效 |
| 在制工单用新料还是旧料？ | 在制工单的用料版本有明确归属 | 新旧料混用，BOM 显示新、实际领旧 |
| 旧料/旧版本库存怎么处理？ | 旧料有"停用/消耗完/报废"方案 | 旧料仍可被新工单领用 |
| 变更能不能撤回？撤回后下游怎么回滚？ | 撤回有记录，且不影响已下达工单 | 撤回把已生效的 BOM 改回去，历史失真 |

**易漏重点**：ECN 是**跨模块**的——BOM、工艺、工单、库存、质量文件（作业指导书）都要同步。只在"变更单"页面看状态，等于什么也没测。

**提示模板**：

```
【任务】核对"物料/工程变更（ECN）"这一段，重点是变更的传播是否完整。
【核对项】
1. 找 2 张变更单，看状态链是否完整（申请→评估→审批→生效），有无审批人与时间；
2. 变更涉及 BOM/工艺的，去对应模块核对该物料当前版本是否真的变了；
3. 在制工单是否被明确划到"旧版本"或"新版本"，两者不能含糊；
4. 旧料/旧版本是否还能被新工单选用（能选 = 变更未生效）；
5. 作业指导书/图纸等文档版本是否跟着变（文档版本与工单不匹配是高频缺陷）。
【产出】表格：变更单/涉及对象/下游是否同步/证据；不同步的写"违反引用完整性 / 口径一致"。
【何时停】若变更需要审批动作才能推进，停；不要代替客户审批。
```

## 8. 设备与工装

**系统里的样子**：设备台账（编码/状态/所属车间）→ 点检/保养计划 → 维修工单/停机记录 → 工装模具（寿命/校验/领用）。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 设备状态有哪几种？谁能改？ | 设备状态（运行/停机/维修/封存）与工单可用性一致 | 停机设备仍能被派工/报工 |
| 点检/保养到期怎么提醒？ | 到期日与提醒逻辑可查；逾期有标记 | 只有计划，没有逾期视图 |
| 停机时长怎么记？ | 停机记录有开始/结束，且不重叠 | 停机记录与 OEE 可用率对不上 |
| 工装有没有寿命计数？ | 工装寿命/使用次数有累计字段 | 寿命到了仍可继续派工，无提醒 |
| 校验/检定有没有有效期？ | 量具/工装校验有效期不为空，过期有标记 | 过期量具仍可关联检验记录 |

**立等式**：`可用率 = (计划时间 − 停机时间) / 计划时间`；拿 OEE 页面的分项自己算一遍（见 `04-industry.md` 3.2）。

**提示模板**：

```
【任务】核对"设备与工装"这一段，只读。
【核对项】
1. 设备台账：状态字段取值是否与业务一致，停机/封存设备是否还能被派工（去派工页反查）；
2. 点检/保养：是否有到期日、逾期标记；计划与记录是否成对存在；
3. 停机记录：开始/结束时间是否成对、是否重叠、合计时长是否与看板一致；
4. 工装：寿命/使用次数是否有累计；校验有效期是否为空或已过期；
5. 若页面有 OEE：抄下可用率/性能/合格率与 OEE，自己乘一遍。
【产出】表格 + 一条可用率算式结论；算不通的标"待业务确认（口径未说明）"。
【何时停】若需设备实时数据（SCADA）才能验证，停；说明"该数据来自 L2，不能用手工录入验证"。
```

## 9. 委外加工（外协）

**系统里的样子**：委外工单/外协单 → 外协发料（带批次）→ 外协收货（回厂检验）→ 加工费结算/损耗处理。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 委外要不要发料？还是供应商自购？ | 发料记录与委外单关联，数量可核 | 只做"收货"，发料在别的模块，两边数量对不上 |
| 外协损耗怎么算？谁承担？ | 收货数 vs 发料数 vs 损耗率有明确规则 | 损耗无记录，直接按"应收"结账 |
| 回厂要不要检验？ | 外协收货挂检验单（来料检/完工检） | 免检流程无标记，等于跳过质量门 |
| 加工费怎么结？按件还是按工时？ | 结算数量 = 检验合格数（不是发货数） | 用发货数结算，报废也算钱 |
| 委外工序在工艺路线里怎么标？ | 工艺路线中的外协工序与委外单一致 | 路线标内制、实际发外协（口径冲突，成本必错） |

**立等式**：`发料数 − 收货合格数 − 报废/损耗数 = 在外协处结存`；`结算金额 = 合格数 × 单价（占位）`。

**提示模板**：

```
【任务】核对"委外加工（外协）"这一段，只读。
【核对项】
1. 抽 1 张委外单，追它的发料记录：数量、批次、时间是否齐全；
2. 收货记录与发料记录做减法，差额（在外协处结存/损耗）是否有说明；
3. 回厂是否有检验单；无检验的，看有没有"免检"标记；
4. 结算数量取的是合格数还是发货数（口径不一致会导致多付加工费）；
5. 工艺路线里该工序是内制还是外协，与委外单是否一致。
【产出】一条从发料到结算的数量链（发料 → 收货 → 合格 → 结算），并标注断点。
【何时停】若结算页需要财务权限，停；记"未覆盖：权限不足"，不要绕。
```

## 10. 成本归集

**系统里的样子**：工单成本（料 + 工 + 费）→ 工时/报工 → 报废损失 → 在制/完工结转。多数 MOM 只到"车间成本"，财务核算在 ERP。

| 该问客户什么 | 该核对什么 | 容易漏什么 |
|---|---|---|
| 成本在哪个系统算？这里只是采集还是核算？ | 明确边界：MOM 出工时/产量，ERP 出金额 | 拿 ERP 的成本规则要求 MOM，越界且测不出来 |
| 材料成本按实际领用还是标准用量？ | 领料数量与成本页的用量口径一致 | 一边标准一边实际，差额无人解释 |
| 工时分摊规则是什么？ | 报工工时 = 成本页工时（同一期间同一工单） | 只对总数，不对单工单 |
| 报废损失算给谁？ | 报废有成本影响字段/单据 | 报废只记数量，成本没扣 |
| 在制期末怎么算？ | 在制金额与在制数量能对上 | 数量对得上、金额对不上（或反之） |

**立等式**：`工单总成本 = 材料 + 人工 + 制造费用`；`单位成本 = 总成本 / 合格数`（分母用合格数不是入库数，需与客户确认口径）。

**提示模板**：

```
【任务】核对"成本归集"，只读，且先划清 MOM 与 ERP 的边界。
【核对项】
1. 先确认：本系统里"成本"是采集数据还是核算结果（看字段有没有金额、有没有凭证号）；
2. 抽 1 张工单：材料（领料金额/数量）、人工（工时×费率）、费用 三项是否齐全；
3. 成本页工时与报工页工时是否一致（同期间同工单）；
4. 报废是否有成本影响；在制数量与在制金额能否对上；
5. 单位成本的分母是合格数还是入库数，页面有没有说明。
【产出】一张成本构成表 + 一条"数量→金额"的核对结论；口径不明的写"待业务确认"。
【何时停】若金额字段需要财务权限或本系统根本没有核算，停；写"未覆盖 + 边界说明"，不要用 ERP 的规则判本系统。
```

## 11. 跨环节串联校验（一条工单走完）

单环节都对、串起来对不上，是最有说服力的缺陷。用**一张真实工单**从计划走到成本，每一站只记一个数：

| 站 | 记什么 | 应该成立 |
|---|---|---|
| 计划 | 计划数量 | ≥ 已投 ≥ 完工 |
| 下达 | 工单状态、工序数 | 未下达不能开工 |
| 领料 | 实领数量 / 退料 | 实领 ≈ BOM 应耗；净领 = 领 − 退 |
| 投料 | 投料数量（按批次） | 投料 ≤ 领料 |
| 报工 | 合格 / 报废 / 在制 | 投入 = 合格 + 报废 + 在制 |
| 检验 | 合格批 / 不合格批 / 让步 | 检验批 = 合格 + 不合格 + 让步 |
| 入库 | 入库数量 | 入库 ≤ 报工合格 |
| 追溯 | 产出批次 ↔ 原料批次 | 双向可查、条数对得上 |
| 成本 | 材料 + 人工 + 费用 | = 总成本；单位成本分母口径一致 |

**提示模板**：

```
【任务】用同一张工单（占位 PO_样例-0001）串联核对 计划→下达→领料→投料→报工→检验→入库→追溯→成本。
【做法】每站只记 1~2 个数（数量/状态/时间），不要一次性抓全字段。
【产出】一张 9 行的链路表：环节 / 读数 / 来源页面 / 是否自洽 / 断点说明。
【要求】任何一站对不上，先回头确认"读的是不是同一张单、同一期间、同一版本"，再定性。
【何时停】若中间某站数据客户方缺失（上游没传），停；写"断点在上游，需客户确认"，不要记成被测系统缺陷。
```

## 12. 三条使用纪律

1. **先立等式，再看页面**。没有等式的核对，最后都会写成"感觉不太对"。
2. **一个环节只问 3~5 个问题**，且都是"客户能当场答"的（谁维护、要不要审批、超了会怎样）。
3. **业务特例不要判 bug**。补单倒填日期、允许超投、免检流程——只要客户说得清规则，就写"待业务确认"，不写"确定错误"。
