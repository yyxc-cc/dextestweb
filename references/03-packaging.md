# 03 · 打包交付：让客户"打开就能看"，而不是"打开一片白"

## 目录结构

```
交付包/
├─ 00-问题清单-单文件.html   ← 主入口（资源内嵌，双击即看，可转发）
├─ 系统名-问题清单.pdf       ← 发人 / 打印（图片单列，无视频）
├─ 00-问题清单.md            ← 纯文字，方便贴群、贴飞书/钉钉文档
├─ 完整演示录像.mp4          ← 一次完整走查
├─ 01-P0-xxx/
│   ├─ 01-….png              ← 标注图，编号即阅读顺序
│   ├─ 02-….png
│   ├─ 复现全过程.mp4
│   └─ 关键片段.gif
├─ 02-P1-xxx/
└─ 06-模块实况对照/          ← 正常模块实拍，证明"这些是有的"
```

编号前缀决定资源管理器里的排序，也决定客户的阅读顺序。`06-模块实况对照` 放在最后，作用是**控预期**：证明页面是齐的，不是"啥都没做"。

## 为什么必须做单文件版

带中文名的相对路径，在这些地方会解析失败：

- 各类编辑器的 HTML 预览面板
- 邮件客户端内嵌预览
- 一些看图/文档软件
- 压缩包解压到别的层级后

结果就是客户说"图片打不开"。把资源 base64 内嵌后，HTML 变成自包含文件：

```bash
node scripts/pack.js --html 00-问题清单.html --name "302MOM-问题清单" --gif-to-mp4
# → 00-问题清单-单文件.html（图片/视频内嵌）
# → 302MOM-问题清单.pdf（打印样式）
```

注意体积：10 MB 左右的单文件 HTML 浏览器没问题，但有些预览面板会卡。**同时给 PDF 作为兜底**，并告诉客户"打不开 HTML 就看 PDF"。

## 截图规格

| 项 | 建议 | 原因 |
|---|---|---|
| 分辨率 | 1600×1000 或 1440×900 | 表格列不挤，标注文字可读 |
| 画面 | **一个像素都不覆盖**，标注全在四周留白里 | 盖住内容 = 对方无法核对，还会怀疑你改过图 |
| 标注 | 左右编号 + 细引线，下方图例，上方结论 | 图本身能讲故事，不依赖正文 |
| 地址栏 | 单独一条深色卡片 | 对方能照着 URL 复现 |
| 一张图 | 只讲一件事 | 多问题混在一起，客户只会记住一个 |
| 正常项 | 也要拍（绿色） | 证明"这一步是对的"，问题定位更可信 |

颜色语义固定：**红=缺陷，橙=待注意/待确认，绿=正常对照**。

验收标准（两条都成立才算合格）：

1. 把标注全遮掉，原图还能当证据用；
2. 把原图遮掉，标注还能读懂在说什么。

`scripts/lib/annotate.js` 就是按这个做的：先截干净图，再在另一个空白页里把图放中间、四周留白、画编号和引线，最后截排版好的画布。所以原图像素一处都没动。

## 视频与 GIF 规格

- 录全程（一次走查），按缺陷切片，不重录
- 切片：动作前 2 秒 → 结果出现后 3~5 秒
- 每段配一句"看什么"（看右下角分页 / 看提示语 / 看已投数量）
- GIF 两遍调色板；`palettegen` 加 `-frames:v 1`；>3MB 就 crop + 降 fps/宽度
- 文件名统一：`复现全过程.mp4`、`关键片段.gif`，客户不用猜

```bash
node scripts/clip.js cut  final.mp4 107 53 "01-P0/复现全过程.mp4"
node scripts/clip.js gif  final.mp4 112 20 "01-P0/关键片段.gif" --width 960 --fps 8
node scripts/clip.js frame final.mp4 131 "01-P0/03-提示语.png"
node scripts/clip.js sheet final.mp4 --times 36,48,60,72 --cols 4 --out 联络表.png
```

## Windows / 中文路径的坑

| 坑 | 现象 | 做法 |
|---|---|---|
| PowerShell 输出中文 | 乱码、路径截断 | 用 Node `fs` 或编辑器工具写文件，不要让 PowerShell 拼中文 |
| `write`/`edit` 工具写中文 | 正常 | 优先用它 |
| 中文名 + 相对路径 | 预览面板打不开图 | 打包成单文件（内嵌 base64） |
| ffmpeg 输出中文文件名 | 报错/乱码 | 先输出到英文临时名，再用 Node `fs.rename` 改成中文 |
| 路径太长 | `ENAMETOOLONG` | 交付包放在桌面/盘根，不要嵌很多层 |

## 测试数据：写进去就要能说清楚

写数据前先记录：

```
订单 PO_xxx（id 1626829454105）quantityInvested 原值 = 1
```

结束后给管理员一张表：

| 项目 | 内容 |
|---|---|
| 新增 | DC1~DC5，挂在 PO_xxx 下，各 1 件 |
| 正常回写 | 该订单已投 0→5、状态 未投产→已投产（应保留） |
| 被污染 | PO_yyy 已投被失败保存从 1 累加到 33（id 已给出） |
| 建议 | 重置为 1，或删除该测试订单 |

**能精确到 id 和原值的清理建议，是"专业"和"闯祸"的分界线。**
